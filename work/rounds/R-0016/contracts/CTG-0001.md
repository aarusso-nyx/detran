## 1. Esquema i18n (M5) — `docs/framework/arch/i18n/dashboard.pt-BR.json`

### 1.1 Forma

- Arquivo JSON plano (uma chave por linha, sem objetos aninhados), chaves em ordem lexicográfica
  crescente (comparação de string simples, como `rait.pt-BR.json`), UTF-8, LF, valores em pt-BR.
- Toda chave é `dashboard.<ns>.<segmentos>` com `<ns>` ∈ os 16 namespaces de §1.2 e cada segmento
  `[a-z][a-z0-9_]*` — **nenhum segmento camelCase, nenhum hífen**.
- Regra de composição no app (única forma admitida de montar chave a partir de token):
  `'dashboard.<ns>.' + token.toLowerCase().replace(/-/g, '_')` — por exemplo
  `dashboard.alert_states.critico_extincao`, `dashboard.errors.alert_state_invalid` (código sem
  o prefixo `DASH.`), `dashboard.indicators.ind_dash_101`, `dashboard.screens.alertas_id.title`.
- Placeholders `{x}` em snake_case (`{as_of}`, `{count}`, `{decision}`, `{threshold}`); nunca `{{`.
- Nenhuma chave fora das listas fechadas de §1.2. Um rótulo que não caiba nelas **não** vira chave:
  TASK-0002/0003 propõem `OD-D16-nnn` no relatório e o Architect adenda este contrato antes do
  CTG-0002 (`plan.md` §Bloqueios, ciclo 2).
- Texto: transcrito da fonte citada em cada lista; onde a fonte só dá o token (sem texto), o
  rótulo é o token em linguagem do console, marcado `(rótulo)` na lista para que o reviewer
  saiba que não é cópia literal.
