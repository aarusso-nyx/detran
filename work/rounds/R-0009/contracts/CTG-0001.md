### 2.1 `portalIdentityClaims`

```text
// backend/domains/portal/identity/src/handwritten/identity.service.ts (exportado por index.ts)
export const PORTAL_ASSURANCE_LEVELS = ['simples', 'avancada', 'qualificada'] as const;
export type PortalAssuranceLevel = (typeof PORTAL_ASSURANCE_LEVELS)[number];
export const PORTAL_GOVBR_LEVELS = ['bronze', 'prata', 'ouro', 'qualificada'] as const;

export interface PortalClaimNames {
  assuranceClaim: string;   // STYNX_COGNITO_ASSURANCE_CLAIM ?? 'custom:assurance_level'
  cpfClaim: string;         // STYNX_COGNITO_CPF_CLAIM       ?? 'custom:cpf'
}
export function portalClaimNames(env = process.env): PortalClaimNames

export interface PortalIdentityClaims {
  cpf: string;                          // exatamente 11 dígitos
  assuranceLevel: PortalAssuranceLevel; // um dos três tokens
  govbrLevel?: (typeof PORTAL_GOVBR_LEVELS)[number]; // observacional, nunca autorização
}

export function portalIdentityClaims(
  principal: Pick<Principal, 'claims'> | undefined,
  names: PortalClaimNames = portalClaimNames(),
): PortalIdentityClaims | null

ordem de leitura de cada claim (primeira chave presente vence; presença = valor !== undefined):
  assurance  → claims['assurance_level']  então claims[names.assuranceClaim]
  cpf        → claims['cpf']              então claims[names.cpfClaim]
  govbr      → claims['govbr_level']      (nome fixo nesta rodada; ver §13 OD-P25)

regras (fail-closed — qualquer falha devolve null, nunca lança, nunca degrada para 'simples'):
  1. principal ausente ou claims ausente/não-objeto                       → null
  2. assurance: não é string, ou string ∉ PORTAL_ASSURANCE_LEVELS
     (comparação exata: sem trim, sem lower-case; 'AVANCADA' e 'avançada' são inválidos) → null
  3. cpf: não é string → null; cpf normalizado = valor com todos os não-dígitos removidos
     (`/\D/g`); comprimento ≠ 11 → null. Não se valida dígito verificador nesta rodada
     (o CPF vem assinado pelo IdP; validar DV é OD-P25).
  4. govbr: string ∈ PORTAL_GOVBR_LEVELS → copiado; qualquer outra coisa → omitido (undefined),
     nunca null do conjunto todo (é observação, não autorização).
  resultado: { cpf: <normalizado>, assuranceLevel, govbrLevel? }
```

```text

posição na cadeia do Nest: guards globais do STYNX (autenticação → tenant → política
DetranPolicyGuard/DetranPolicyEvaluator) executam ANTES de qualquer guard de controlador.
Logo a guarda de identidade roda DEPOIS da autenticação e DEPOIS da política. Consequências:

  - a guarda nunca substitui a política: uma rota que esqueça @Resource/@Action continua barrada
    por verify:decorators, não por esta guarda.

  1. principal = principal autenticado do STYNX na requisição HTTP (mesmo acessor usado pelo
```

```text
// identity.service.ts

  unitários injetam relógio fixo 2026-09-14.

export interface ActLevelDecision {
  actKey: string; required: 'none' | PortalAssuranceLevel; current: PortalAssuranceLevel; policyId: string;
}

async assertActLevel(
  tx: Transaction,                 // transação do comando (withTenantContext), nunca nova conexão
  identity: PortalIdentityClaims,  // saída da guarda (portalIdentityOf(request))
  actKey: string,

leitura (parametrizada, sob RLS do tenant da transação):
  select id, minimum_assurance from portal.act_level_policy
   where act_key = $1 and enabled = true
     and effective_from <= $2::date and $2::date < coalesce(effective_to, 'infinity'::date)
   order by effective_from desc limit 1          -- $2 = clock.today()

  0 linhas                              → PortalError('PORTAL.INTERNAL', 500, { actKey })
                                          (ato sem linha NUNCA libera — M4)

                                          (RN-PORTAL-101 verificação (c); UC-PORTAL-019 AC-3)

  assuranceRank(current) < assuranceRank(required)

                                             actKey, required, current,

nunca consulta claims.govbrLevel (UC-PORTAL-019 AC-2: decide-se pelo nível, não pela cor do selo).
```
