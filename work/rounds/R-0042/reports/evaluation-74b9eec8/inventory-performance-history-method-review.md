# Inventory-performance historical-input method review

Auditor, read-only. **The proposed interpretation is consistent with the original contract and existing native semantics.** A genuine candidate-X reading of `inventory_performance` can measure an explicitly frozen historical canonical dataset. Selecting that current reading for X's scorecard is not borrowing an older candidate's result. Its input dataset and its measurement identity are different things; both must be disclosed.

Direct original evidence: R-0041 `evaluation-0e26c795-20261022/evaluation-register.json`, F4:T7, already calls the result measured and expressly states that the installed store reader “pools retained inventory durations across epochs and statuses,” with exact population in `pooled-inventory-duration-inputs.json`, and “is not a current-only timing baseline.” BL-0023 expressly requires investigation of the archived historical duration population, distinction from current execution, unchanged 2000/5000 ms thresholds and no purging historical readings to improve the result. These original obligations govern the interpretation; no new permission or calibration is needed.

Inspected installed 2.7.0 `measureInventoryPerformance`: configured/default readingsDir is `.devai/state/sensor-readings`; it scans subdirectories beginning `inventory_`, JSON entries, and admits finite nonnegative numeric `duration_ms` values whose sensor kind begins `inventory_`. It filters neither source commit nor status. It pools those durations and computes per-kind and global metrics against the original thresholds. Unsupported/malformed/no-duration entries are skipped by the actual implementation. Therefore “38 inventory files exist” is a directory census, not automatically “38 durations admitted.” The supplied manifest must distinguish these populations and explain every exclusion according to actual code.

Required custody for the final audit:

- Freeze the configured root, actual read timing/order and complete store census at the measurement moment. Record every included source file's canonical path, reading ID/kind/status/source identity/timestamp, duration and SHA256; preserve missing fields as missing rather than fabricate older provenance.
- Enumerate excluded inventory-prefixed entries and the actual exclusion reason (missing/invalid/negative/nonfinite duration, parse failure or kind mismatch). Confirm total/per-kind admitted counts agree with the emitted metrics, and retain the genuine complete output/capture and official immediate receipt.
- Identify which input records are tracked historical source, earlier 74 epoch, current-X prior emissions or another retained epoch. The later required second pass may legitimately use a larger historical pool; freeze its actual inputs separately and explain resulting count/metric changes rather than silently compare unlike pools.
- Bind the new reading itself to the current frozen candidate through the real producer identity, native source/lineage resolution and official record. The canonical X scorecard must select the genuine current-X reading, not an old F4:T7 reading merely because its historical metrics look useful.
- Label the result “native inventory performance over retained historical durations,” never current-only benchmark, fresh timing of every inventory kind or performance certification. Keep BL-0023's original residual distinct from whether its measurement is supported.

Do not empty the store, delete/filter old histories, change readingsDir/thresholds or alter native code to manufacture an isolated benchmark. None is required by the anti-pooling rule. That rule prohibits filling X's cells from older result readings or summing measured-cell counts across SHAs; it does not prohibit an installed history sensor from genuinely measuring its declared historical inputs at X.

The exact 211/38 historical census and its future emitted result remain pending the promised actual manifest. No sensor was rerun, no final grid populated and no source or state changed by this audit. C6/#211 and resource holds remain intact.
