## 2. Tipos comuns — `forms/form-gate.ts`

### 2.1 `FormGate` e `FieldMask`

```text
import type { RaitCommand } from '../data/models/commands';        // §3: chave M8
import type { RaitErrorCode } from '../core/error-codes';          // catálogo §3
import type { RaitRoleCode } from '../app.route-manifest';         // 13 papéis canônicos (M4)

export interface GatePrecondition {
  readonly note: string;      // texto literal da fonte (spec §7 coluna "Pré-condição", §9 coluna "Validação", RN)
  readonly source: string;    // ex.: 'rait-web-frontend.md §7', 'rait-web-frontend.md §9', 'RN-RAIT-142'
}
export interface FormGate {
  readonly preState: readonly string[] | null;     // tokens do agregado alvo do comando (§5 diz qual); null = criação
  readonly roles: readonly RaitRoleCode[];         // papéis da linha de RAIT_COMMAND_RULES da chave mapeada no §3 (verdade em runtime)
  readonly preconditions: readonly GatePrecondition[];
  readonly command: RaitCommand;                   // M8 '<recurso>:<ação>' ∈ RAIT_COMMANDS
  readonly postState: string | null;               // token pós-transição; null = estado inalterado
  readonly errorCodes: readonly RaitErrorCode[];   // ⊆ RAIT_ERROR_CODES
}
export type FieldMask = 'cpf' | 'cnpj' | 'placa' | 'ait' | 'date' | 'protocol';
export const FIELD_MASK_PATTERNS: Readonly<Record<FieldMask, string>> = {
  cpf: '000.000.000-00', cnpj: '00.000.000/0000-00', placa: 'AAA0A00',
  ait: '',              // formato do número do AIT sem fonte no corpus lido → source_pending (OD-R12-039); campo livre
  date: 'dd/mm/aaaa',   // exibição pt-BR; o valor do controle é sempre 'YYYY-MM-DD' (build-pack §0.4)
  protocol: 'RAIT-0000-000000',  // forma das fixtures (CTG-0002b C-2B-02 'RAIT-2026-000001'); formato oficial → OD-R12-039
};
export function documentMaskFor(raw: string): 'cpf' | 'cnpj'   // ≤ 11 dígitos → 'cpf'; senão 'cnpj'
```

Um `FormGate` é **documentação verificável** (padrão do Portal `form-gate.ts`): transcreve a
tabela §6.6/§7/§9 da spec, os workflows e o catálogo; **nunca** decide permissão — isso é
`*stynxHasPermission` com a chave de `RAIT_COMMAND_RULES` (M4) e o servidor. `roles` vem da
linha real de `policy.ts` (não da §7 nem da ficha) — as divergências estão no §3.

`today` é **injetado**: a página deriva `'YYYY-MM-DD'` de `RaitClock.now()` (CTG-0002b §3.2) e o
entrega em `context.today`; `forms/` nunca chama `new Date()`/`Date.now()` (§6.1). A comparação
de datas civis ISO é lexicográfica — nenhuma aritmética de data no cliente.

### 2.3 Mensagens de forma

Toda `issue` do zod vira **chave i18n** por `issueMessageKey` (§2.2): regras próprias fixam
`message` = chave do §7; as demais caem em `rait.forms.common.*`. A página renderiza a mensagem
sob o campo (`issue.path`), com `aria-describedby` (guia §3.7); issues com `path: []` (regra do
formulário inteiro) vão para o topo do formulário. Erro de negócio (`StynxError`) continua no
`ErrorBoundary`/`<rait-error-banner>` (catálogo §4; CTG-0002b §4.4) — nunca no schema.

### 2.4 `context` — fatos do servidor espelhados (nunca decididos)

Todo schema cujo formulário tem regra dependente de dado do servidor recebe `context:
z.strictObject({ … })` no valor do formulário. A página preenche `context` com o que as facades
já carregaram; `forms/` nunca busca nada. Convenção **tri-estado**: `tristate =
z.boolean().nullable()` — `false` (fato conhecido e adverso) → issue de forma na chave da regra;
`true` → passa; `null` (fato não disponível no cliente) → **sem issue**: o servidor decide e
devolve o código da coluna "erro do servidor". Listas (`impededMemberIds`, `criticalCaseIds`,
`businessDays`) e contagens (`extensionCount`, `returnCount`) seguem o mesmo princípio: vazias/`null`
= sem fato. `context` **não é controle** (nenhum `<input>`) e **não vai ao servidor** (o mapeamento
para o DTO — R-0007 — o ignora). Estados (`caseState`, `sessionState`) são espelhados com
`z.enum(<TOKENS>).nullable()` e a regra `rait.forms.common.state_invalid` (path do campo principal)
só dispara quando não-nulo e fora de `preState` do gate.
