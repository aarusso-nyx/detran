### 3.1 Fato do contrato gerado (determina a forma de `list*`)

Nos oito arquivos gerados, **nenhuma** operação `list*` aceita query (`parameters.query?: never`)
e todas respondem `200` com **array plano** `components['schemas'][X][]` ("most recent first,
capped at 500"), não com o envelope `{ items, total, page, pageSize }` da build-pack §0.1. Nenhum
`paths` de comando existe (spec §11 linha 1). Consequências fixadas aqui (OD-R12-018 registra a
lacuna para o Architect de R-0007):

1. O cliente **não envia query string** em `list*` (nada fora do contrato) e converte o array em
   `ListPage<T>` no cliente por `applyListQuery` (§3.2).
2. `q` e `filtro` são estreitamento **por igualdade/substring em campos declarados** (tabela
   §3.3, coluna "spec"); `ordem` só admite `'padrao'` = ordem recebida do servidor — nunca se
   reordena no cliente ([RN-RAIT-141]); `page`/`pageSize` fatiam o array já estreitado.
3. `total` = tamanho do array estreitado (≤ 500); a UI rotula listas com `LIST_SERVER_CAP` só
   quando `total === LIST_SERVER_CAP` (banner `rait.common.list_capped`, chave (P) do §9.2).

  export function applyListQuery<T>(items: readonly T[], query: ListQuery, spec: ListQuerySpec<T>): ListPage<T>;
     // (1) filtro: para cada [campo, valor] de query.filtro com campo ∈ spec.filtro → mantém item se String(item[campo]) === valor;

### 3.4 `session.client.ts` de sessão STYNX (IU-RAIT-018)

A ficha `IU-RAIT-018` cita `data/api/session.client.ts` para "claims da sessão STYNX". Não existe
`paths` para isso: a página `/conta` lê `RaitSessionFacade` (`core/session.facade.ts`, CTG-0002a §4)
— `roles()`, `canonicalRoles()`, `permissions()` — e nenhum cliente HTTP. O nome
`session.client.ts` fica reservado ao **colegiado** (`SessionClient`, §3.3).

  export interface ReadSlot<T> { readonly status: Signal<ReadStatus>; readonly error: Signal<ClassifiedError | null>;
                                 readonly value: Signal<T | null>; readonly key: Signal<string | null>; readonly loadedAt: Signal<number | null> }
  export interface ReadStore<T> extends ReadSlot<T> {
    load(key: string, loader: () => Promise<T>, options?: { force?: boolean; emptyWhen?: (value: T) => boolean }): Promise<void>;

### 4.2 Mapa evento SSE → facade (invalidação; CTG-0002a §6 `RaitStreamEvent`)

Cada facade injeta `SseService` e, na construção, assina `events$` (só os tipos da sua linha),
`tick$` e `resync$`; `tick$`/`resync$` → `refresh()` de todo slot com `key` não nula.
Evento → `invalidate(key)` do slot + `refresh()` se o slot estiver carregado com essa chave (ou
qualquer chave, para listas). Páginas L2 chamam `sse.connect({ topics, caseId?, sessionId? })`
(idempotente) na criação; `disconnect` não é chamado por página (o serviço é global).

| Evento (`RaitStreamType`) | Facades e slots invalidados                                                                                                                                                                                                                                                                                                                                            |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `case.changed`            | `CaseFacade` (`caso`, `partes`, `prazos`, `relogios`, `documentos`, `diligencias`, `minutas`, `admissibilidade`, `comunicacoes`, `eventos`, `impedimentos`, `decisao` do `caseId`), `QueueFacade` (todas as listas), `ProtocolFacade` (todas), `SigningFacade` (`fila`; `caso` se `caseId`), `ArchiveFacade` (`busca`, `dossie` se `caseId`), `AuditFacade` (`trilha`) |
| `assignment.changed`      | `QueueFacade` (`filaDefesa`, `filaRelator`, `retomar`, `painel`), `RadarFacade` (`drilldown` se `caseId`), `CaseFacade` (`caso` se `caseId`)                                                                                                                                                                                                                           |
| `clock.flag-changed`      | `RadarFacade` (`radar`, `incidentes`, `drilldown` se `caseId`), `CaseFacade` (`relogios` se `caseId`), `QueueFacade` (todas — a ordem do servidor pode mudar), `SessionFacade` (`pautaCandidatos`, `extraordinaria`)                                                                                                                                                   |
| `session.changed`         | `SessionFacade` (`sessoes`, `sessao` se `sessionId`)                                                                                                                                                                                                                                                                                                                   |
| `agenda-item.changed`     | `SessionFacade` (`sessao` se `sessionId`, `vistas`, `pautaCandidatos`)                                                                                                                                                                                                                                                                                                 |
| `batch.changed`           | `SessionFacade` (`lotes`, `lote` se `batchId`, `relatoria`)                                                                                                                                                                                                                                                                                                            |
