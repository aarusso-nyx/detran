## Regras fixas

1. `apps/boat/mobile/src/lib/ports.ts` não muda: interfaces, tokens e `BOAT_PORTS` ficam
   byte a byte. As implementações só `implements` as interfaces existentes.
2. Nenhum import `@capacitor/*` (#109) nem chamada de rede (`fetch`, `HttpClient`,
   `XMLHttpRequest`) em `src/lib/ports/`. Nenhum RENAEST (#120).
3. Nenhuma chave i18n nova e nenhum texto pt-BR: as portas expõem tokens de máquina. O texto
   de UI vem com as páginas (TASK-0006).
4. Toda classe declara `readonly adapterName`, `readonly mode = 'homologacao'` e
   `readonly securityLevel` (padrão de `BrowserEncryptedStoreAdapter`: `adapterName`,
   `securityLevel`). O selo `homologacao` é o de OD-R28-001.
5. Dependências de navegador entram por um objeto `options` opcional no construtor e são lidas na
   chamada, nunca no construtor. Assim a ausência vira `unavailable` em vez de exceção de
   construção e os specs injetam dublês. Quando a chave está presente em `options` com valor
   `undefined`, o adaptador usa `undefined`, o que permite provar o caso indisponível.
6. Nenhum provider é registrado por padrão (`providedIn: 'root'` proibido). Só a função de
   providers abaixo liga token → classe, fora de spec.
7. Uma falha nunca devolve dado inventado: nada de coordenada padrão, foto sintética, assinatura
   vazia com sucesso ou atestação `valid` (ADR-0033 §Fronteira 3).

## Erro de máquina comum

Arquivo `apps/boat/mobile/src/lib/ports/boat-port-error.ts`:

```ts
export type BoatPortName = (typeof BOAT_PORTS)[number];
export type BoatPortErrorCode =
  | 'permission-denied'
  | 'unavailable'
  | 'timeout'
  | 'cancelled'
  | 'invalid-input'
  | 'integrity-failure'
  | 'unattested';
export const BOAT_PORT_ERROR_CODES: readonly BoatPortErrorCode[]; // os 7, nesta ordem
export class BoatPortError extends Error {
  override readonly name: 'BoatPortError';
  readonly port: BoatPortName;
  readonly code: BoatPortErrorCode;
  constructor(
    port: BoatPortName,
    code: BoatPortErrorCode,
    options?: { cause?: unknown },
  ); // message === code
}
export function isBoatPortError(value: unknown): value is BoatPortError;
export interface BoatHomologationAdapter {
  readonly adapterName: string;
  readonly mode: 'homologacao';
  readonly securityLevel: string;
}
```

Os sete tokens são provisórios, `source_pending:OD-R28-004`: `boat-error-catalog.md` não cobre
falhas de dispositivo. Eles seguem a convenção de token kebab já usada na biblioteca
(`boat-extension-route-unavailable`) e no TEAT (`indexeddb-unavailable`). `message` é o próprio
token, e a causa original vai em `cause`. Mapeamento uniforme de `DOMException.name`:
`NotAllowedError`/`SecurityError` → `permission-denied`;
`NotFoundError`/`NotSupportedError`/`NotReadableError` → `unavailable`; `AbortError` →
`cancelled`. Qualquer outra exceção de API vira `unavailable`, com `cause`.

## Contrato da atestação (OD-R28-002)

`AttestationPort.attest()` retorna `Promise<{ deviceId; attestation }>` e a assinatura não muda.
Em homologação, o "não atestado" é explícito por dois meios, sem mudar a interface:

1. **Rejeição tipada:** toda chamada rejeita com `BoatPortError`, com `port = 'AttestationPort'`
   e `code = 'unattested'`. Nenhum caminho do arquivo resolve a promessa.
2. **Propriedade de adaptador:** `attestationStatus = 'unattested'` e `mode = 'homologacao'`
   permitem que a UI mostre o estado antes de chamar.

A UI bloqueia o ato que exigir atestação. A lista desses atos é `source_pending:OD-R28-014`.
Recomendação: lista vazia nesta rodada, com a porta implementada e sem consumidor.

## Decisões do Architect

- **OD-R28-002 = (a), fechada.** A porta web rejeita com `unattested` explícito e a UI bloqueia o
  ato que exigir atestação (ADR-0033 §Fronteira 2–3: nada de mock silencioso).
- **OD-R28-003 = (a), fechada.** Cópia na biblioteca, como `BoatBrowserEncryptedStoreAdapter`,
  com teste de paridade. O pacote comum (b) toca `packages/ui`/R-0024 e fica como candidato
  posterior. O nome é distinto para não colidir, no host TEAT mobile, com a classe do TEAT.

## Paridade com `BrowserEncryptedStoreAdapter`

A classe BOAT exporta `BOAT_ENCRYPTED_STORE_CRYPTO` (objeto congelado) com os valores abaixo, e o
spec de paridade compara cada um com o literal correspondente em
`apps/teat/mobile/src/app/data/local/local-act.store.ts`.

| Aspecto                                         | TEAT (`local-act.store.ts`)                                                                         | BOAT (`BoatBrowserEncryptedStoreAdapter`)                                           | Paridade  |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | --------- |
| Chave                                           | `generateKey({ name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt'])`                      | idem (`algorithm: 'AES-GCM'`, `keyLength: 256`, `extractable: false`)               | igual     |
| Persistência da chave                           | store `cryptographic-metadata`, chave `device-sealing-key`                                          | idem, pelo backend                                                                  | igual     |
| IV                                              | `crypto.getRandomValues(new Uint8Array(12))` por gravação                                           | idem (`ivBytes: 12`)                                                                | igual     |
| Texto cifrado                                   | AES-GCM de `JSON.stringify(value)`                                                                  | idem; `value` é `string`                                                            | igual     |
| Digest canônico                                 | SHA-256 hex minúsculo do valor canônico                                                             | idem (`digest: 'SHA-256'`); o canônico de uma string é a própria string serializada | igual     |
| Registro                                        | `{ id: '<collection>:<key>', collection, canonicalDigest, initializationVector, ciphertext }`       | idem, com `collection = 'boat-kv'`                                                  | igual     |
| Stores e versão                                 | `encrypted-records` (`keyPath: 'id'`), `cryptographic-metadata`, versão `1`                         | idem (`recordsStore`, `metadataStore`, `databaseVersion: 1`)                        | igual     |
| `securityLevel`, `encryptionScope`, `encrypted` | `'software-sealed'`, `'device'`, `true`                                                             | idem                                                                                | igual     |
| Banco                                           | `detran-teat-mobile`                                                                                | `detran-boat-mobile` (nenhum dado compartilhado com o TEAT)                         | diferente |
| `adapterName`                                   | `teat-indexeddb-webcrypto`                                                                          | `boat-indexeddb-webcrypto`                                                          | diferente |
| Interface                                       | `MobileEncryptedStorePort` de `@stynx-nyx/mobile-runtime` (`put/get/list/remove/clear` por coleção) | `MobileEncryptedStorePort` de `ports.ts` (`get(key)`, `set(key, value)`)            | diferente |
| Erros                                           | `Error('indexeddb-unavailable')` e similares                                                        | `BoatPortError` (§Erro de máquina comum)                                            | diferente |

Backend de registros: `interface BoatSealedRecordBackend { readRecord(id: string):
Promise<BoatSealedRecord | undefined>; writeRecord(record: BoatSealedRecord): Promise<void>;
readKey(): Promise<CryptoKey | undefined>; writeKey(key: CryptoKey): Promise<void> }`. O padrão é
IndexedDB, com os stores acima. O spec usa backend em memória, porque o jsdom não tem IndexedDB e
nenhum pacote pode ser instalado. A chave é carregada ou gerada uma vez por instância (promessa
memorizada), como no TEAT.

de componente ou de rota no host (CTG-0003). Nenhum outro arquivo não spec registra esses tokens.
