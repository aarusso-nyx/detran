`…000030000003` e ata `…000034000001`; `40:27` falhou no FK

documentos da história legada. `60` isolado passou na caracterização, mas só a
aplicação do perfil inteiro prova que ela basta.

**Sensor Inspector:** aplica separadamente `fresh`, `legacy-upgrade` (com sua
pré-condição) e o novo perfil; compara os manifests históricos; reaplica o
novo. Consulta as FKs de `inf.rait_jeton_line` para `rait_pool_member`,

## C-02-02 — mock SEFAZ-AM

O mock proposto `tools/stack/mocks/sefaz-mock.mjs` é Node nativo sem pacote
novo, escuta somente `127.0.0.1:3999`, documenta `GET /health` e serve apenas
sob o prefixo `/mock`.

| Método | Rota                               | DTO                   | Exemplo determinístico de teste                                                                                                                        |
| ------ | ---------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| POST   | `/mock/sefaz/payments/lookup`      | `DebtLookupOutput`    | `debts: [{ debtId: 'test-debt-001', amount: 123.45, status: 'OPEN' }]`, `inActiveDebt: false`, `requestId`                                             |
| POST   | `/mock/sefaz/guides`               | `IssueGuideOutput`    | `guideId: 'test-guide-001'`, `referenceNumber: 'TEST-REF-001'`, `amount: 123.45`, `expiresAt: '2026-12-31T23:59:59Z'`, `status: 'ISSUED'`, `requestId` |
| GET    | `/mock/sefaz/payments/{reference}` | `PaymentStatusOutput` | `TEST-REF-001`, `status: 'PAID'`, `amountPaid`, `paidAt`, `receiptNumber`, `requestId`                                                                 |
| POST   | `/mock/sefaz/rectifications`       | `RectificationOutput` | `rectificationId: 'test-rectification-001'`, `status: 'UNDER_REVIEW'`, `requestId`                                                                     |
| POST   | `/mock/sefaz/refunds`              | `RefundOutput`        | `refundId: 'test-refund-001'`, `status: 'PENDING'`, `requestId`                                                                                        |
| GET    | `/mock/sefaz/refunds/{refundId}`   | `RefundStatusOutput`  | `test-refund-001`, `status: 'APPROVED'`, `approvedAt`, `requestId`                                                                                     |

Toda resposta inclui os campos obrigatórios de `domain.ts`, e opcionais têm tipo
válido. POST ecoa `body.requestId` quando presente. Sem ele, inclusive GET sem
corpo, gera `requestId` determinístico marcado como teste e sem segredo. Esses
IDs e datas são fixtures operacionais, não código normativo.

Corpo JSON malformado ou inválido, verbo não permitido e referência ou refund
desconhecido retornam envelope JSON
`{ requestId, error: { category, code, message, retryable, providerStatus } }`.
Usam somente categorias de `errors.ts`: `BUSINESS_ERROR` para corpo inválido e
`NOT_FOUND` para identificador desconhecido, ambos não-retryable; `405` traz
`Allow`. Não se inventa código normativo.

**Sensor Inspector:** percorre as seis rotas pelo próprio `SefazHttpAdapter`,
um POST com request ID explícito, GETs sem corpo, referência desconhecida, corpo
inválido e verbo inválido; fixa DTO, echo ou geração de ID, normalização em
`SefazAdapterError`, ausência de dependência e escuta somente IPv4 loopback.

## C-02-04 — externos off e 503 comprovado

O backend mantém um principal local único e os cinco papéis padrão de CTG-0001:
`technical-admin`, `agency-admin`, `field-agent`, `rait-coordinator`,

## C-02-06 — checkpoint (b)

Com worktree limpa e sem processo ou stack remanescente, executar nesta ordem:

```bash
pnpm stack:db-reset
pnpm stack:start
pnpm stack:health
pnpm stack:smoke
pnpm stack:stop
pnpm stack:smoke
```

Os primeiros cinco devem terminar 0; o último termina não-zero porque o backend
está parado. `db-reset` só usa `detran_local_stack` e sua guarda de
`apply.sh --full`, sem remover volume. `start` usa `fresh-local-stack`, aguarda
SEFAZ e `stop` não deixa processo. 503 não alcançado ao adapter torna o smoke
bloqueado, nunca equivalente a verde.
