## Fronteira e autoridade

Este contrato define a caracterização da abertura e sua repetição no fechamento. A
TASK-0002 testa o contrato; a TASK-0003 implementa `tools/devai/baseline.mjs` e os
scripts. O maestro materializa `baseline.json`/`baseline.md` antes de qualquer
mudança de código e `baseline-final.json`/`baseline-final.md` no fechamento. Só o
maestro grava prova por `devai evidence record` e toca `record/`. Art. 6 rege a
autoria por caminho; Art. 7 rege os papéis; Art. 41 exige prova append-only.

O HEAD de abertura indicado no plano é
`c848723c1ee9053233b7e08732c5b80bbe06d625`. O executor deve verificar o SHA
completo do HEAD imediatamente antes da primeira leitura e gravá-lo em ambas as
saídas. Se o HEAD não for esse SHA, a caracterização para e pede ao maestro uma
decisão de rebase da medição; o script não rotula outro commit como abertura. A
tabela de `a92ef731` no plano é histórica e não preenche a linha de base oficial.

O script de medição é somente leitura. Sua interface contratada é
`pnpm devai:baseline --out-dir <diretório>`; ele escreve apenas os dois arquivos
no diretório indicado, de modo determinístico. O maestro escolhe a localização
versionada e executa a rodada inicial antes de mudar código. A repetição final
usa o HEAD final explícito e nomes `baseline-final.*`. Nenhum resultado parcial
vira PASS: erro de leitura, fonte indisponível ou formato desconhecido preserva
`source_pending` e o diagnóstico, sem fabricar zero.

**Clarificação de testabilidade C-01-T1 (mesmo critério):** o executável aceita
`--repo-root <diretório>` opcional, com padrão na raiz da worktree. Esse parâmetro
permite ao Inspector montar um repositório de fixture em diretório temporário e
provar os casos de linha órfã/ancorada e tarefa válida/inválida sem depender das
contagens mutáveis da worktree. O script não escreve no repo-root indicado; só
escreve em `--out-dir`. Eixos ausentes da fixture ficam `source_pending`, sem
fabricar PASS ou zero. Os testes não exigem que a árvore viva conserve tarefas
inválidas depois do CTG-0003, nem executam a medição integral repetidamente quando
uma fixture pode caracterizar a regra.

**Clarificação de retomada C-01-T2 (mesmo critério):** `c848723c1ee9053233b7e08732c5b80bbe06d625`
continua o HEAD de abertura de R-0020, mesmo após a integração de R-0017. O
maestro materializa a medição oficial em clone descartável fixado nesse commit,
antes de publicar qualquer código de R-0020. O script lê e relata o HEAD do
`--repo-root` quando ele é um repositório Git; a verificação de que a medição
oficial usa o SHA de abertura cabe ao maestro. Uma fixture temporária sem Git
preserva `source_pending` para o HEAD, sem fabricar o SHA de abertura. A medição
final lê o HEAD integrado então vigente e mantém o mesmo formato. Nenhum dado
histórico é substituído ou promovido a PASS por esta clarificação.

## Formato determinístico

`baseline.json` é UTF-8, com LF e uma quebra final. A ordem das chaves e das
coleções é fixa. O formato lógico abaixo é o contrato de saída; os objetos
`raw` preservam campos nativos sem renomear estados do DEVAI:

```json
{
  "schema_version": "1.0.0",
  "round_id": "R-0020",
  "head_sha": "<SHA completo medido>",
  "sources": [{ "path": "<fonte>", "sha256": "<digest>" }],
  "checks": {
    "members": [
      {
        "id": "<id>",
        "argv": [],
        "exit_code": null,
        "raw": {},
        "source_pending": null
      }
    ],
    "suite_members": ["ledger-local", "ledger-rc"]
  },
  "scorecard": {
    "cells": [],
    "counts": {},
    "observations": {},
    "source_pending": null
  },
  "sensors": {
    "registry_count": 59,
    "read_kind_count": 49,
    "readings": [],
    "counts": {},
    "presets": {},
    "source_pending": null
  },
  "rounds": { "items": [], "counts": {}, "source_pending": null },
  "proofs": {
    "chain_head": "<hash>",
    "chain_records": 0,
    "jsonl_lines": 0,
    "anchored": 0,
    "orphans": [],
    "duplicate_anchors": [],
    "source_pending": null
  },
  "tasks": { "items": [], "counts": {}, "source_pending": null },
  "pull_requests": { "items": [], "counts": {}, "source_pending": null },
  "mixed_commits": { "items": [], "counts": {}, "source_pending": null }
}
```

Os números acima são apenas constantes das políticas lidas ou marcadores de
tipo; `chain_records: 0` no exemplo não é uma medição. Nenhum `0`, lista vazia ou
`null` substitui fonte inacessível: o eixo afetado traz `source_pending` com
motivo e seus contadores desconhecidos ficam `null`. Ordenar fontes e itens por
caminho/identificador, PR por número, commit por hash, células por F/T, erros
por caminho/campo/regra. Não incluir relógio, caminho absoluto da worktree,
ordem de retorno da rede nem informação volátil. JSON idêntico no mesmo HEAD e
nas mesmas fontes deve ter bytes idênticos.

`baseline.md` deriva somente do JSON, com HEAD, fontes, tabela dos oito eixos,
contagens e diagnósticos `source_pending`, e listas de órfãs, tarefas inválidas e
commits mistos. Não contém fatos adicionais, inferência de piso A1 ou status
promovido a PASS. Os arquivos finais repetem o mesmo formato no HEAD final e
incluem comparação campo a campo contra a abertura. A comparação preserva os
valores brutos de cada membro e célula. Aplicar estas regras de não regressão:

- `checks`: membro com `ok: true` na abertura continua `ok: true`; a contagem
  de membros com falha não cresce. Mudança de escopo ou de argumentos é exibida,
  sem comparação silenciosa entre populações diferentes.
- `scorecard`: nenhuma célula antes PASS deixa de ser PASS. O piso de PASS por
  substrato fica pendente de A1.
- `sensors`: nenhuma leitura persistida da abertura desaparece; falha de
  sensor não é reclassificada como PASS pela medição.
- `rounds`: fechamento antes presente não desaparece nem muda para estado
  diferente de `closed`; PC e referências anteriores continuam rastreáveis.
- `proofs`: toda linha nova é ancorada; linhas órfãs não declaradas e âncoras
  duplicadas não aumentam. Uma correção append-only é registrada sem apagar
  a órfã histórica.
- `tasks`: o total de inválidas e ilegíveis não aumenta para o mesmo conjunto
  de tarefas; cada TASK nova deve ser válida.
- `pull_requests`: PR com trailer na abertura o conserva; PR novo desta rodada
  contém `Inv-Compliance:` e papel declarado.
- `mixed_commits`: nenhum commit novo da rodada mistura F2/F3, quando houver
  fonte canônica de classificação.

Qualquer violação é FAIL, não REVIEW. `source_pending` em qualquer lado impede
declarar PASS para a comparação afetada; o relatório identifica a dependência.
Os membros obrigatórios finais de `check` também dependem de A1 e não são
escolhidos por esta tarefa.
