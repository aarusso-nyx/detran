## Definições que valem como contrato

- `get(key, { agencyId?, on?, required? })` escolhe a versão efetiva para `on` e resolve na ordem
  agência específica → tenant → default do catálogo para a surface derivada da chave.
- O mapeamento fechado de prefixo para surface é: `rait|collection|deadline|session` → `rait`;
  `teat|sync` → `teat`; `portal|privacy` → `portal`; `est` → `est`; `dashboard` → `dashboard`.
  Qualquer outro prefixo falha fechado; os testes não podem inferir fallback.
- Versão efetiva: `effective_from <= on` e (`effective_to is null` ou `on <= effective_to`), maior
  precedência e depois maior `effective_from`/`version`.
- `required=true` sobre versão `source_pending=true` lança código
  `RAIT.PARAMETER_SOURCE_PENDING` somente para chave RAIT, contexto apenas `{ key }`. Nesta rodada
  os testes de erro pending obrigatório cobrem apenas RAIT; aliases BOAT/DASHBOARD ficam adiados
  até seus primeiros consumidores.
- PUT em linha `legal_readonly=true` lança `RAIT.PARAMETER_LEGAL_READONLY`; vigência anterior à
  data fixa lança `RAIT.PARAMETER_EFFECTIVE_DATE_PAST`; `If-Match` ausente dá 428
  `RAIT.IF_MATCH_REQUIRED`; versão divergente dá 412 `RAIT.VERSION_CONFLICT`.
- Sucesso cria uma nova linha com `version + 1`, preserva a anterior, exige motivo/decisão/vigência,
  obtém tenant e actor do `RequestContext`, emite `PARAMETRO_ALTERADO` na mesma transação e invalida
  somente o cache daquele tenant/chave. Replay idempotente igual não duplica; payload diferente
  com a mesma chave idempotente dá 409 `RAIT.IDEMPOTENCY_REPLAY`.
- RLS: tenant B não lista, lê nem altera linhas do tenant A. `tenant_id` de payload é rejeitado/não
  faz parte do DTO.
- O catálogo legal não é editável e a tabela possui os checks/índice únicos definidos por
  TASK-0001.

## Critérios de aceitação

- `pnpm --filter @detran/ops-parameter test:unit` → coleta pelo menos um teste unitário; antes de
  TASK-0003 pode falhar apenas por comportamento/arquivos manuscritos ainda ausentes.
- `env DETRAN_TEST_TIER=integration pnpm --filter @detran/ops-parameter exec vitest run tests` → coleta
  pelo menos um teste de integração; pode falhar pelo comportamento ainda ausente, nunca por
  sintaxe, tier vazio ou fixtures inventadas.
- `pnpm format:check` → formato verde.
- A matriz no relatório cobre precedência, data efetiva, pending required/opcional, legal readonly,
  data passada, 428, 412, idempotência, nova versão/evento/cache e RLS cross-tenant.

teste; não crie tenants/personas fora das fixtures; não use `skip`/`todo`; não edite gerados.
