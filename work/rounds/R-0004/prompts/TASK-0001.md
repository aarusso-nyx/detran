## Tarefa

Crie o blueprint `BP-OPS-PARAMETER-001`, regenere apenas pelos scripts canônicos e escreva o
contrato Markdown manual do comando `PUT /v1/ops/parameters/{key}`. Esse documento arquitetural
não é OpenAPI nem JSON gerado. O CRUD gerado deve expor somente leitura (`list`, `get`); toda
mutação será pelo controller manuscrito referenciado no blueprint.

## Definições que valem como contrato

- Módulo: `Parameter`, namespace `ops`, versão `1.0.0`, pacote `@detran/ops-parameter`, DDL
  `15-ops-parameter.sql`, owners `detran-ops`.
- `testAliases`: `[{ package: '@detran/shared', target: '../../shared/src/index.ts' }]`, para os
  testes resolverem o código-fonte compartilhado sem exigir `dist/` pré-construído.
- Entidade/tabela: `Parameter` / `ops.parameter`.
- Colunas exatas da ADR: `id uuid`, `tenant_id uuid`, `traffic_agency_id uuid?`, `scope`,
  `surface`, `key varchar(120)`, `value_json jsonb`, `value_type`, `status`,
  `source_pending boolean`, `legal_readonly boolean`, `decision_ref varchar(40)`,
  `legal_basis text?`, `reason text`, `version int`, `effective_from date`,
  `effective_to date?`, `changed_by uuid`, `created_at timestamptz`.
- Checks: `scope in ('tenant','agency','surface')`; surface em
  `('rait','teat','portal','est','dashboard','shared')`; status em
  `('vigente','a_confirmar','proposta')`; `version > 0`; fim nulo ou não anterior ao início.
  Não invente enum para `value_type`.
- Índice único exatamente sobre tenant, agência nula normalizada, surface, key e vigência. Use uma
  expressão SQL determinística para o nulo; não substitua a semântica por um índice que permita
  duplicatas quando `traffic_agency_id` for nulo.
- O blueprint referencia `handwritten/parameter.service` como provider/export e
  `handwritten/parameter-command.controller` como controller/export, mas não cria esses arquivos.
- API gerada: base `/v1/ops/`, recurso `parameters`, resource key `parameter`, operações somente
  `list` e `get`.
- PUT: ator `agency-admin`; headers `If-Match` obrigatório e `Idempotency-Key`; body exige
  `value`, `valueType`, `reason`, `decisionRef`, `effectiveFrom`, e aceita `trafficAgencyId`,
  `scope`, `surface`, `status`, `sourcePending`, `legalBasis`; `tenant_id` nunca entra no payload.
  Sucesso 200 retorna a nova versão e `ETag`; a mudança cria versão, não sobrescreve histórico.
- Erros canônicos: 428 `RAIT.IF_MATCH_REQUIRED`; 412 `RAIT.VERSION_CONFLICT`; 422
  `RAIT.PARAMETER_LEGAL_READONLY`; 422 `RAIT.PARAMETER_EFFECTIVE_DATE_PAST`. Não crie código novo.
- Evento de sucesso: `PARAMETRO_ALTERADO`, gravado na mesma transação e usado para invalidar cache.
