## Tarefa

Implemente um parser compartilhado e dois CLIs (`generate-seed.mjs` e verificador), produza os três

## Definições que valem como contrato

- O contrato completo é a seção escrita por TASK-0004 e os testes de TASK-0005; não crie exceções
  ou allowlists para fazer fixtures passarem.
- O gerador escreve atomically e só muda o arquivo quando bytes diferirem. `--check` nunca escreve
  e falha se qualquer gerado estiver ausente/stale.
- SQL parametrizável não se aplica ao seed estático, mas todo literal vindo do Markdown precisa de
  escaping SQL robusto. A execução é idempotente pelo índice natural e não apaga versões alheias.
- O verificador examina apenas fontes runtime, ignora os diretórios definidos pelo contrato e
  devolve mensagem acionável + exit 1 em qualquer violação.
- Flags: todas e somente linhas tipo `F`; defaults booleanos; overrides `DETRAN_FEATURE_*`
  preservados; o alias legado `DETRAN_FEATURE_SPEED_METERS` continua controlando
  `teat.speed_meters`, cujo default continua false e que continua controlando `SpeedModule`.
- Não implemente nem simule a view normativa.

## Critérios de aceitação

- `pnpm parameters:test` → executa `node --test tools/parameters/tests/*.test.mjs`, todos verdes.
- `pnpm parameters:generate` seguido de `pnpm verify:parameter-catalogue` → gerados atuais e gate OK.
- `pnpm verify:parameter-catalogue` → mensagem resume quantidade de entradas/flags e zero erros.
- `pnpm --filter @detran/app test:unit` → verde, incluindo defaults/overrides de flags.
- `pnpm check` → verde com o novo gate dentro da cadeia.
- `pnpm build` → verde, com `@detran/ops-parameter` construído imediatamente antes de
  `@detran/app`.
- `pnpm format:check` → verde.

não silencie refs/chaves desconhecidas; não mexa no módulo normativo.
