## 1. Limites e taxonomia

Este contrato destila o corpus já publicado; não cria regra de produto, papel,
estado, prazo ou valor. O catálogo de cliente abaixo é a proposta M2 e só se
torna taxonomia resolvida após o binding DEVAI do `adopter-policy.json`:

| Classe               | Domínios                                    |
| -------------------- | ------------------------------------------- |
| Cliente, proposta M2 | `INF`, `EST`, `CH`, `OPS`, `PORTAL`, `DASH` |
| Core já declarado    | `SEC`, `AUTH`, `DATA`                       |

`law/policy/adopter-policy.json` terá `schemaVersion: "1.0.0"`,
`policy_id: "detran-law-corpus"`, `policy_version: "1.0.0"` e apenas a
extensão adotadora `domains.client` com os seis códigos da proposta M2. Ele não
altera `glob_guards`, `thresholds` ou `scorecard_na`.

## 3. `trace.json` plan

`law/trace.json` is version `1.0.0` with exactly the nine IDs in §2, once each.
For each entry, `docs` repeats the corresponding `authority_docs.docs`,
`code_areas` identifies the cited implementation area and `tests` has exactly
the existing test path listed in §2, its matching suite and `target_type:
"test"`. It contains no inferred path, generated digest or assertion count.

`test_corpus` is `[]`. DEVAI discovery currently finds no test file under
`packages/**/tests/*.test.ts` or `tests/**`; the trace therefore must not assert
execution, manufacture a digest, or add the backend test paths to `test_corpus`.

## 4. Schema roster M3 and gate rule (a)

The roster is every file matching
`node_modules/@aarusso-nyx/devai/dist/runtime/index/schemas/*.schema.json` in
the installed DEVAI `1.5.6` package. TASK-0003 copies each one byte-for-byte to
`law/schemas/` and writes `law/schemas/manifest.json` with the package version
and one SHA-256 per copied filename.

Rule **(a)** compares the complete filename set, each copied byte stream and
each manifest SHA-256 against `--package-schemas-dir`. A missing, extra, altered
or hash-divergent schema is a violation. The gate does not format, normalize or
repair a schema copy.

## 5. Provenance gate rule (b)

Rule **(b)** resolves every ID in `provenance` and in `authority_docs` against
these closed forms and locations:

| Family | ID regex                       | Resolution                                                                                         |
| ------ | ------------------------------ | -------------------------------------------------------------------------------------------------- |
| RN     | `^RN-[A-Z]+-[0-9]{3}$`         | `docs/framework/product/**/rules/<id>.md`                                                          |
| WF     | `^WF-[A-Z]+-[0-9]{3}$`         | `docs/framework/product/**/workflows/<id>.md` or `docs/framework/product/shared/workflows/<id>.md` |
| UC     | `^UC-[A-Z]+-[0-9]{3}$`         | `docs/framework/product/**/use-cases/<id>.md`                                                      |
| JRN    | `^JRN-[A-Z]+-[0-9]{3}$`        | `docs/framework/product/**/journeys/<id>.md`                                                       |
| APP    | `^APP-[A-Z0-9]+$`              | a `docs/framework/product/**/APP.md` whose front matter declares the ID                            |
| ADR    | `^ADR-[0-9]{4}$`               | `docs/meta/adr/<id>-*.md` or `law/adr/<id>-*.md`                                                   |
| OD     | `^OD(?:-[A-Z0-9]+)*-[0-9]{3}$` | a table row in `docs/meta/knowledge-base/open-decisions-rait.md`                                   |

For a document reference, the gate also requires the path to exist and the
anchor to match the slug of an actual Markdown heading in that document. It
does not accept an RN front matter field, prose, or a near match as an anchor.
An unresolved ID, path or anchor is a violation; `source_pending` is retained
as text where a source is absent and does not authorize a fabricated ID.

## 6. Obsolete-content gate rule (e)

Rule **(e)** scans every README below `law/` and `product/` that has content. It
fails on either exact obsolete phrase, with no silent tolerance:

- `Content is intentionally empty until authored.`
- `Generated by DEVAI v1.4.5.`

### Clarificação C-01-06.1 — placeholder isolado

Um README que contém somente o placeholder gerado é isento enquanto seu
diretório não tiver outro arquivo substantivo e o próprio README não tiver
corpo autoral além do placeholder. Essa isenção cobre, no estado atual,
`law/glossary/README.md` e `product/README.md`.

Quando houver qualquer outro arquivo substantivo no diretório, ou corpo autoral
no README, cada uma das duas frases passa a ser uma violação da regra (e). A
isenção não alcança `law/adr/README.md`, pois seu diretório contém ADRs, nem
qualquer diretório já povoado. C-01-06 e o RED de `OD-R19-001` permanecem
inalterados.

At contract time `law/adr/README.md` contained both phrases despite existing
ADR content. R-0018 PR #128 repaired it; this resolution does not narrow rule
(e) or transfer the R-0018 write boundary.

## 7. Gate interface and acceptance criteria

TASK-0005 implements this exact public interface, with repository defaults and
exit status 0 for no violations and 1 otherwise:

```text
node tools/law/verify.mjs --repo-root <path> --package-schemas-dir <path> --od-registry <path>
```

It synchronously exports:

```js
verifyLawCorpus({ repoRoot, packageSchemasDir, odRegistryPath });
// => { violations: [{ rule, code, path, detail }] }
```

| Criterion | Required result                                                                                                           |
| --------- | ------------------------------------------------------------------------------------------------------------------------- |
| C-01-01   | `CTG-0001.md` is non-empty and defines the M2 policy, nine closed IDs and the trace plan.                                 |
| C-01-02   | Each M2 client and each `SEC`, `AUTH`, `DATA` entry is active, readiness-bearing and linked to an existing test in §2.    |
| C-01-03   | Every authority document anchor is a verified Markdown-heading slug; RN provenance is never substituted for an anchor.    |
| C-01-04   | Rule (a) rejects a missing, extra, byte-different or SHA-different M3 schema.                                             |
| C-01-05   | Rule (b) rejects unresolved provenance, path, document anchor or OD; `OD-R19-*` resolves in the canonical R-0019 section. |
| C-01-06   | Rule (e) rejects either obsolete phrase. It remains expected RED until the R-0018-owned README has removed both phrases.  |
| C-01-07   | The CLI and synchronous export have exactly the interface stated above.                                                   |

The task acceptance commands are `test -s work/rounds/R-0019/contracts/CTG-0001.md`
and `pnpm format:check`.
