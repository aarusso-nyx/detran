blueprint = ordem do prompt. Tabelas de projeção (2.14…2.20) carregam `last_event_id`, `event_schema_version`,

## 4. Mapa de projeções

Princípios (ADR-0020; M5): cada projetor consome **só** eventos publicados em `main` ou, quando o app não publica,
os eventos **propostos** aqui (marcados `proposta`); aplica idempotente por `event.id` via o ledger único
`dashboard.monitor_projection_applied_event` (chave `(tenant_id, projection_name, event_id)`), dentro da transação
do chamador, gravando `event_schema_version` (= `version` do envelope RAIT/TEAT/PORTAL ou `schemaVersion` do envelope
BOAT — forma de `dashboard-crashes.projection.ts`) e `aggregate_version` (= `aggregate.version`); evento com
`aggregate.version` menor que o da célula → `ignored: stale_version` (ledger gravado mesmo assim); replay a partir de
`integration.outbox` (única leitura cruzada admitida, M5/M6). Um projetor casa `consumedEvents` contra
`event.type` **ou** `event.domainEvent` (precedente BOAT de R-0010: `SINISTRO_*` são `domainEvent`). Nenhuma
projeção escreve de volta; nenhuma célula guarda nome, CPF, placa, nº de processo ou dado de saúde.

**`connected` (M5, regra aplicada no §4.2):** `true` somente quando **todo** evento de que o indicador precisa para o seu
estado/limiar tem produtor em `main` (`grep` em `backend/domains/**/src`, fora de testes); `false` quando o sinal
essencial não é publicado, mesmo que a projeção consuma um evento auxiliar. Produtores encontrados em `main`
(HEAD `08fb84e8`): RAIT `rait.case.changed`, `rait.case.received`, `rait.case.admitted`, `rait.case.withdrawn`,

  'dashboard.monitor_projection_applied_event';

export const DASHBOARD_MONITOR_PROJECTIONS = [
  'dashboard.prescription_risk',
  'dashboard.production',
  'dashboard.integration_health',
  'dashboard.pec_deadlines',
  'dashboard.teat_measures',
  'dashboard.portal_service_metrics',
  'dashboard.duty_evidence',
  'dashboard.source_freshness',
] as const;
export type DashboardMonitorProjectionName =
  (typeof DASHBOARD_MONITOR_PROJECTIONS)[number];

/** Envelope como integration.outbox.payload o guarda (rait-events-sse-contract §1);
 *  version (RAIT/TEAT/PORTAL) ou schemaVersion (BOAT) — um dos dois obrigatório. */
export interface DashboardConsumedEvent {
  id: string;
  type: string;
  domainEvent?: string;
  version?: number;
  schemaVersion?: number;
  occurredAt: string;
  tenantId: string;
  actor?: { kind: 'user' | 'system' | 'timer'; id?: string; role?: string };
  correlationId?: string;
  causationId?: string;
  aggregate: { kind: string; id: string; version: number };
  data: Record<string, unknown>;
}

export interface DashboardSqlTransaction {
  query<T extends Record<string, unknown> = Record<string, unknown>>(
    statement: string,
    values?: readonly unknown[],
  ): Promise<{ rows: T[]; rowCount?: number | null }>;
}

export interface DashboardProjectionContext {
  /** Transação aberta pelo chamador (Database.tx); ledger e efeito na mesma transação. */
  tx: DashboardSqlTransaction;
  /** Tenant da sessão RLS; deve ser igual a event.tenantId (senão erro tenant_mismatch). */
  tenantId: string;
  /** Relógio injetado; nunca Date.now(). */
  now: Date;
}

export type DashboardProjectionResult =
  | {
      kind: 'applied';
      projection: DashboardMonitorProjectionName;
      cells: number;
    }
  | { kind: 'duplicate'; projection: DashboardMonitorProjectionName }
  | {
      kind: 'ignored';
      projection: DashboardMonitorProjectionName;
      reason: 'stale_version' | 'not_relevant';
    };

export type DashboardProjectionErrorReason =
  'event_not_consumed' | 'data_invalid' | 'tenant_mismatch' | 'version_missing';

/** Erro tipado (código genérico DASH.INTERNAL do catálogo; nenhum código novo — M13/regra 3):
 *  message = `DASH.INTERNAL:<reason>:<eventId>` (precedente PORTAL.INTERNAL de R-0009). */

  readonly code: 'DASH.INTERNAL';
  readonly reason: DashboardProjectionErrorReason;
  readonly eventId: string;
  readonly projection: DashboardMonitorProjectionName;
  constructor(
    projection: DashboardMonitorProjectionName,
    reason: DashboardProjectionErrorReason,
    eventId: string,
    detail?: string,
  );
}

export interface DashboardProjector {
  readonly projection: DashboardMonitorProjectionName;
  /** = consumedEvents do arquivo, como dados (ADR-0020 Decisão 4). */
  readonly consumedEvents: readonly string[];
  /** Ordem: (1) type/domainEvent ∈ consumedEvents senão throw event_not_consumed;
   *  (2) tenantId = ctx.tenantId senão throw tenant_mismatch; (3) version|schemaVersion ≥ 1
   *  senão throw version_missing; (4) data válida para o evento senão throw data_invalid;

   *  stale_version; evento consumido sem célula a tocar ⇒ ignored not_relevant; (7) efeito ⇒ applied. */
  apply(
    event: DashboardConsumedEvent,
    ctx: DashboardProjectionContext,
  ): Promise<DashboardProjectionResult>;
}

 *  true = primeira vez (segue o efeito), false = duplicate. Grava event_type, versões e occurred_at. */

## 7. Gate `verify:domain-boundaries` (M6 como especificação executável)

Vive em `tools/domain-boundaries/verify.mjs` (R-0010, A2), generalizado por TASK-0003; testes `node --test` em
`tools/domain-boundaries/tests/*.test.mjs` (TASK-0011). Script raiz `"verify:domain-boundaries": "node
tools/domain-boundaries/verify.mjs"` entra em `pnpm check` logo após `verify:senatran-boundary`.

### 7.1 Regras

1. **Varredura:** todo arquivo `.ts`/`.mjs` sob `backend/domains/**/src/**`, exceto `tests/`, `*.spec.ts`,
   `vitest.config.ts`, `dist/` e `src/generated/`. `backend/app/src` (raiz de composição) fica **fora** nesta rodada
   (OD-D16, impresso como aviso `skipped: backend/app/src (OD-D16)`).
2. **Dono do arquivo:** o segmento imediatamente após `backend/domains/` mapeado para o schema de domínio:
   `inf → inf`, `est → est`, `ch → ch`, `portal → portal`, `dashboard → dashboard`, `ops → ops`, `shared → (nenhum)`.
3. **Acesso SQL detectado:** expressão regular, sem distinção de caixa, sobre cada literal/template do arquivo:
   `\b(from|join|into|update|delete\s+from)\s+([a-z_]+)\.([a-z_]+)\b` — captura `<schema>.<tabela>`.
4. **Violação:** `<schema>` ∈ {`inf`, `est`, `ch`, `portal`, `dashboard`} e `<schema>` ≠ dono do arquivo.
5. **Admitidos (nunca violação):** schemas de plataforma `ops.*` e `integration.*` (parâmetros, agência, outbox,
   espelhos), `auth.*`, `audit.*`; qualquer tabela cujo nome termina em `_ref` (vocabulário global, DDL `1x`, sem
   tenant) em qualquer schema; leituras cruzadas em arquivos cujo nome termina em `.projection.ts` **e** que exportam
   `consumedEvents` literal não vazio (`export const consumedEvents = [ '…', … ] as const` — a regex do gate exige ao
   menos um literal de string entre os colchetes).
6. **`.projection.ts` sem `consumedEvents`** (ausente, vazio, ou não literal) → violação própria, mesmo sem leitura
   cruzada: `projection without consumedEvents`.
7. **Dívidas declaradas:** lista **no próprio script**, cada entrada `{ file, table, od }`, **impressa** a cada
   execução como `known debt: <file> reads <table> (<OD>)`; hoje uma:
   `backend/domains/ops/field/src/handwritten/shift-readiness.ts` lê `inf.normative_mobile_package` (OD-D15). Uma
   entrada da lista que não corresponde mais a uma violação real → aviso `stale debt` (não falha — remover na
   rodada seguinte); qualquer violação fora da lista → falha.
8. **Saída:** sucesso `domain boundaries verified (N files)` + avisos + dívidas, exit 0; falha lista `violation:
<file>:<line> <schema>.<table> (owner <dono>)` uma por linha, resumo `domain boundaries: K violations`, exit 1.

### 7.2 O que o gate **não** cobre (declarado)

Leituras via repositório/ORM sem literal SQL (não existem no repositório — SQL parametrizado é a regra,
`CODESTYLE.md` §Backend); `backend/app/src` (OD-D16); pacotes fora de `backend/domains`.

1. Positivo: árvore com `inf/x/src/a.ts` lendo `inf.foo` e `dashboard/monitor/src/handwritten/projections/b.projection.ts`
