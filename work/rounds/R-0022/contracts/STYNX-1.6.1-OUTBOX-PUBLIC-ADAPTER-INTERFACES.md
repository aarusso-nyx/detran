## Shared append adapter

Keep the existing `SqlTeatEventOutbox` class and `TeatEventOutbox.append(tx, envelope): Promise<{id:string}>`; its identity is used by `ops/core/src/runtime.ts` to prevent duplicate sinks. Add constructor `constructor(native?: Pick<OutboxService, 'appendInTransaction'>)` using public-root types. No argument preserves the existing legacy branch and its tests. An explicitly supplied malformed native binding refuses; it must not select the legacy branch accidentally.

When native is supplied, require the received actual transaction query capability (otherwise public `OutboxEventTransactionError('transaction_role')`). Read trusted tenant through `select auth.current_tenant() as tenant_id` on that same transaction, requiring exactly one nonempty actual tenant (otherwise `OutboxEventTransactionError('tenant')`). Never fall back to envelope.tenantId on this branch. Create an independent payload envelope with the actual SQL tenant, keeping its input id sentinel unchanged. Call only native.appendInTransaction with that very transaction and `{entity: envelope.type, entityId: envelope.aggregate.id, idempotencyKey: outboxIdempotencyKey(resolvedEnvelope), payload: resolvedEnvelope}`. Do not open/commit another transaction, write native tables directly, generate an event UUID, append a legacy event in parallel or mutate the caller's envelope. Return the actual native row.id; native refusal/errors propagate unchanged. Reject an incoherent returned tenant or absent id with the public transaction error rather than inventing a successful receipt.

The native service independently checks actual app-role READ COMMITTED writable primary context and trusted Database tenant, and owns tenant-clock/event insertion inside the supplied transaction. This wrapper does not replace those checks. Stored native payload.id remains the caller's sentinel; projection into payload.id happens at the read boundary below. Therefore this branch is not an assertion that old raw SQL payload/history readers already match.

## Confirmed offline ordinary ACK capability gap

Published `SubmitSyncBatchOptions` (types.d.ts409–429) supplies transport identity, requestBody, archived-only replay callback and response status/header methods. It has no ordinary body formatter/finalizer or pre-apply consumer metadata ingress. `postgres-durable.js`1203–1238 constructs the native result with acceptedItems=input.items.length and batchId=deviceBatchId, serializes that fixed result, and persists bytes in a later SDK-owned durable transaction. Item applier/event/concurrency/conflict ports run before complete batch results and cannot finalize the consumer's seven-field legacy ACK atomically with that close. The public legacyIdempotencyStore is read/archive replay integration, not an ordinary finalization write port. No reviewed public transaction callback closes this gap.

Consequently ordinary legacy accepted count, independently generated consumer batch/receipt identity for every nonapplied outcome, and exact legacy raw ACK bytes cannot be declared preserved by post-return response rewriting, native-key-to-UUID conversion, a private table write, archived-only callback or parallel non-atomic cache. Preserve a specific upstream capability checkpoint for a supported ordinary response/consumer provenance finalization seam; continue genuine local applier, numbering-rule, classifier, reservation and outbox append/read work independently. Do not wire an ordinary command/provider path that silently changes those required semantics or label inactive source parity. Existing explicit provider/trust blockers are separate from this public API limit.

## CTG mapping clarification before F3 assertions

The native event additionally retains `metadata: {aggregateType: envelope.aggregate.kind}`, as already required by CTG0008 §2.2 and the existing R22 native appender. Its omission from the preceding field enumeration was an incomplete enumeration, not a supersession of that mapping. Malformed explicitly supplied native binding or missing query capability uses public `OutboxEventTransactionError('transaction_role')`; absent/incoherent actual SQL tenant or returned native tenant uses reason `'tenant'`; absent returned id uses `OutboxEventTransactionError()` without inventing a reason. An omitted constructor argument selects the unchanged legacy branch; an explicitly supplied undefined is equivalent to omission, while null or other malformed supplied binding refuses.
