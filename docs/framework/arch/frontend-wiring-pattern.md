# Padrão de ligação dos frontends (v0)

**Versão:** v0 (R-0033 TASK-0001, Architect, 2026-10-15). **Escopo:** descreve o código de `main`
de `apps/rait/web` **como ele é hoje**, sem variantes, costura por costura: arquivo, símbolo, o que
uma rodada J (C-0003 §2 item 2; para o `rait-web`, R-0025) **liga** e o que **não muda**. É a
referência que `work/rounds/R-0025/command-gap-analysis.md` §4 cita ("cliente de comando único de
`frontend-wiring-pattern.md`"). R-0024 `stynx-dedup` **absorve** este padrão (kit de app único,
cliente de comando único, costura SSE única) e não o substitui (C-0003 §4): o que R-0024 mover
para `@detran/ui`/STYNX mantém os contratos descritos aqui. O modo prévia
(`frontend-preview-mode.md`) se encaixa nas mesmas costuras (§11).

Estado de partida comum a todas as costuras: todas as **leituras** estão ligadas aos `GET`
gerados; todos os **comandos** (64 métodos, `data/models/commands.ts` `RAIT_COMMANDS`) lançam
`RaitCommandUnavailableError('<recurso>:<ação>')` antes de qualquer requisição (decisão M8 de
R-0012, `todo(R-0007 CTG-0004)` em cada método).

## 11. Encaixe do modo prévia

O modo prévia (`frontend-preview-mode.md`) substitui por `useClass` exatamente as costuras de
injeção desta lista — os 8 clientes (§1), `RaitSessionFacade`/`StynxSessionService` (§8),
`RaitClock` (§6) e `RaitStreamTransport` (§7) — e nada acima delas. Quando uma rodada J ligar um
comando, o adapter de prévia correspondente deixa de chamar `super` e lança
`RaitCommandUnavailableError` com a mesma string (D-15 do contrato da prévia), para que a prévia
continue "não funcional" e nunca alcance a rede.
