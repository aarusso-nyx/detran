# PEC specification-debt register

This register records origin PEC behavior that has no dedicated approved use case. Porting a
mechanism here preserves observable behavior without silently promoting its legacy implementation
into product authority. Domain-specific effects remain fail-closed until an approved rule or use
case defines them.

| Origin module                                  | Port decision                                                          | Preserved behavior                                                                                                                                                                     | Explicit boundary                                                                                                                                                                                                                                     |
| ---------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `process-blocks-workflow`                      | Port as `ch/process-blocks`                                            | Tenant-scoped, encounter-linked active block; idempotent source/kind registration; actor-attributed resolution; active blocks can gate other approved workflows.                       | The module does not decide which business event creates a block, what a new block kind means, or whether it may be resolved. Those decisions remain with the originating approved workflow.                                                           |
| `billing-billing`                              | Rebuild as `ch/billing`                                                | Items, payment validation, normalized one-invoice-per-item membership, attestation, and divergences; exam charges bind the exact effective federal public-price version.               | No clinic-supplied exam amount is accepted. Each medical/psychological price has federal source, publication date, annual IPCA reference, and validity. Telehealth items bind the ported session by foreign key.                                      |
| `telehealth-telemedicine`                      | Port as `ch/telehealth`                                                | Start and conclude a session only with successful LFD, preserve encounter/professional/appointment linkage, and optionally create a billable item.                                     | Raw session URLs are not persisted because they may contain access credentials. The port stores a canonical provider and opaque external session identifier; connection-token exchange remains an external adapter concern.                           |
| `clinical-controls`                            | Port as `ch/clinical-controls`                                         | Encounter-scoped ophthalmology, sleep, devolutive, satisfaction, and supervised-intern participation events with kind-specific payload validation and actor attribution.               | The event ledger does not grant authorship or signing authority. Optional exam references are typed and must belong to the same encounter; candidate requests, scheduling and completion now use the separately authorized candidate-dossier surface. |
| `inconsistencies`                              | Port as `ch/inconsistencies`                                           | Detection, notification marking, correction, reprocessing, and closure with separate evidence fields, exact forward-only transitions, due timestamp, and actor attribution.            | The origin does not dispatch its documented webhook. The port does not invent a recipient or payload contract: `NOTIFIED` records the domain milestone only, and external delivery remains blocked on an approved integration contract.               |
| `complaints`                                   | Defer to `portal/ouvidoria`                                            | The origin table and workflow map to reviewed `UC-PORTAL-016`, not to a PEC-specific complaint aggregate.                                                                              | Shared durable idempotency/rate-limit infrastructure is now demonstrated. The feature remains deferred because its approved owner is Portal/Ouvidoria, not PEC; this port does not create a competing complaint aggregate.                            |
| `admin-operational-controls`                   | Port records as `ch/operational-controls`; scheduling already absorbed | Inspection, credentialing, sanction, location, dashboard, backup, support, and release records; clinic-location validation; grouped counts.                                            | The generic ledger records evidence but does not create product authority for sanctions, credentialing, backup, release, support, or dashboards. Weekly professional schedules already live in `ch/scheduling`.                                       |
| `admin-process-parameters`                     | Absorb into kernel tenant settings                                     | Normalized list/upsert/delete and persistent tenant feature evaluation use `tenancy.tenant_settings.settings.ch.processParameters`; no duplicate PEC configuration table exists.       | Mutations are schema-validated, size-bounded, actor-attributed, audited, idempotent and row-locked. Feature definitions require a scalar default and optional tenant overrides; no in-memory fallback is permitted.                                   |
| `integration-councils` / `admin-professionals` | Port council validation into `ch/clinical-network`                     | Active medical and psychological professionals require a tenant-scoped CRM/CRP verification receipt; provider responses are reduced to status, check time, identity and response hash. | This preserves the origin's council gate only. It does not claim the annual entity/professional accreditation, biennial proof, specialist-title, or federal-authorization lifecycle described by draft RN-PEC-115.                                    |
