# ADR-0053: Native round index compatibility

## Status

Accepted by Architect under the Owner authorization to close R-0037 and execute all necessary C2–C8 repairs.

## Context

The repository regeneration tool emitted four columns. DEVAI 2.6.3 round seal requires five columns and an explicit truthful terminal marker. Native evidence rendering is correctly constrained to .devai/state/render and cannot install a governed index directly. Seal therefore refused PC-0023 with ROUND_ARCHIVE_PHASE_LEDGER_MISSING. No archived proof or closure was corrupt.

## Decision

Align the existing machine regeneration tool with the native closure-index format, sorted by round and following supersession chains. Derive terminal=yes only for the unique validated head. Keep all rejection checks for missing targets, cross-round supersession, branching and cycles. Never bypass seal or relax its parser. Rebuild only record/derived/indexes/rounds.md; preserve every proof/closure byte and existing round seal.

## Validation and consequences

Existing corruption counterexamples remain mandatory. Add a terminal-marker tampering counterexample and compare the generated bytes to the native renderer. The repair is a bounded prerequisite to sealing R-0037 and part of the authorized compatibility campaign, not a product change. Closure acceptance continues to distinguish C1 scoped acceptance from the native global security FAIL.
